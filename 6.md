# Filtering Data

**Objectives.** After completing this lesson, the successful student will be able to:

1. Use the WHERE clause of a SELECT statement to filter the results of a query.
2. Filter the rows of a query result to match against a single value.
3. Filter the rows of a query result to look for non-matched values.
4. Filter the rows of a query result to check against a range of values.
5. Filter the rows of a query result to find rows without a value.

## Using the WHERE Clause

All the example queries you have encountered to this point in this resource have retrieved all of the rows from a database table. Usually, you will not need all of the rows from a table to meet your data needs. It is possible to create a SELECT statement that retrieves specific rows from a database table. These statements require the WHERE clause.

::: {.term}
> **WHERE** — The clause in a SELECT statement that is used to filter the rows retrieved by a query.
:::

The WHERE clause is used to define a condition or set of conditions that must be met for a row to be returned in a query result. These criteria are generally designed as a logical test that compares values for a column on a table to target values. Those values that meet the conditions are returned in the query result. Suppose you want an alphabetized list of the artists, and their nationality, who were born in the year 1861. You can use a chat with an AI assistant to create the SELECT statement that will do this:

::: {.ai-conversation prompt="Write a SQL statement to display an alphabetized list of artists and their nationality. Show only those artists born in 1861."}
> To display an alphabetized list of artists and their nationality, showing only those artists born in 1861, you can use the following SQL statement:
>
> ```sql
> SELECT full_name, nationality
> FROM artist
> WHERE birth = 1861
> ORDER BY full_name;
> ```
>
> This query selects the full_name and nationality columns from the artist table. The WHERE clause filters the results to include only artists born in the year 1861. The ORDER BY clause sorts the results in alphabetical order based on the full_name column.
:::

**Try the SQL statement.**

```sql {.websql .data-art}
SELECT   full_name, nationality
FROM     artist
WHERE    birth = 1861
ORDER BY full_name;
```

::: {.note}
> This is one of the book's interactive query boxes (tied to the `artist`/`work`/`museum` schema diagram, with a "Play" button and results panel) — shown here as a plain code block until that component is built on this platform.
:::

The query returns an alphabetized list of the artists and their nationality. There are nine artists retrieved by this query, even though there are 421 artists on the artist table. The nine artists retrieved all meet the condition set by the WHERE clause that the artist was born in 1861.

::: {.note}
> **The Position of the WHERE Clause.** The WHERE clause must appear third in the SELECT statement. Since the SELECT and FROM clauses are required in all SELECT statements, they appear first and second. All other clauses appear after the WHERE clause (notice the position of the ORDER BY clause in the example query above).
:::

Consider the syntax of the WHERE clause. Generally a WHERE clause creates a logical test comparing values using a mathematical operator. In this example, the WHERE clause uses a logical test comparing the values in the birth column of the artist table with the value 1861. Those values on the table that are equal to 1861 meet the condition and will be retrieved by the query. Those that do not meet the condition are excluded from the query result. Only nine of the 421 artists in the table meet it.

## The WHERE Clause Operators

You can use a number of different mathematical operators to compare values in the logical tests in the WHERE clause. Generally, these are constructed to compare the values in a column on the left side of an operator to a value on the right side (column = value). The example above uses the "=" operator, which requires that the values on the left side of the operator (in this case the values in the birth column) exactly match the value on the right side (the year 1861). The table below describes operators that can be used to compare values in the WHERE clause.

#### WHERE Clause Operators

| Operator | Description | Example |
|:---:|---|---|
| `=` | The values in the specified column match a stated value | `birth = 1861` |
| `<>` | The values in the specified column do not match a stated value | `birth <> 1861` |
| `!=` | The values in the specified column do not match a stated value | `birth != 1861` |
| `<` | The values in the specified column are less than a stated value | `birth < 1861` |
| `<=` | The values in the specified column are less than or equal to a stated value | `birth <= 1861` |
| `!<` | The values in the specified column are not less than a stated value | `birth !< 1861` |
| `>` | The values in the specified column are greater than a stated value | `birth > 1861` |
| `>=` | The values in the specified column are greater than or equal to a stated value | `birth >= 1861` |
| `!>` | The values in the specified column are not greater than a stated value | `birth !> 1861` |
| `BETWEEN` | The values in the specified column are within the range of two stated values | `birth BETWEEN 1860 AND 1861` |
| `IS NULL` | The values in the specified column are NULL (without data) | `birth IS NULL` |

## Checking Against a Single Value

The most basic WHERE clauses compare the values in a column to a single value. This is demonstrated in the last example. In the example, the value in the birth column had to be 1861 for the row to be included in the query result. Consider two more examples using different operators.

Assume you want to list artists, their nationality, and their birth for artists born before 1400. You can use a chat with an AI assistant to create the SELECT statement that will retrieve this data:

::: {.ai-conversation prompt="Write a SQL statement to display a list of artists, their nationality, and their birth. Show only those artists born before 1400."}
> To display a list of artists, their nationality, and their birth, showing only those artists born before 1400, you can use the following SQL statement:
>
> ```sql
> SELECT full_name, nationality, birth
> FROM artist
> WHERE birth < 1400;
> ```
>
> This query selects the full_name, nationality, and birth columns from the artist table. The WHERE clause filters the results to include only artists born before the year 1400. The resulting rows will contain the artist's full name, nationality, and birth year.
:::

**Try the SQL statement.**

```sql {.websql}
SELECT   full_name, nationality, birth
FROM     artist
WHERE    birth < 1400;
```

The query retrieves the name, nationality, and birth for artists born before 1400. There is only one artist born before 1400. Note that for an artist to be born before 1400, their birth year would be less than 1400.

You may want to also modify the last query to include any artists that were born in 1400 as well as those born before 1400. You can use a chat with an AI assistant to create the SELECT statement that will retrieve this data:

::: {.ai-conversation prompt="Adjust the query to include artists who were born in 1400."}
> To adjust the query to include artists who were born in 1400, you can modify the comparison operator in the WHERE clause. Here's the updated SQL statement:
>
> ```sql
> SELECT full_name, nationality, birth
> FROM artist
> WHERE birth <= 1400;
> ```
>
> In this modified query, the WHERE clause includes the less than or equal to (<=) operator instead of just the less than (<) operator. This ensures that artists born in the year 1400 are included in the result set. The query will display the full name, nationality, and birth year of artists born before or in 1400.
:::

**Try the SQL statement.**

```sql {.websql}
SELECT   full_name, nationality, birth
FROM     artist
WHERE    birth <= 1400;
```

In this query, the operator in the WHERE clause was modified to include those artists born in 1400. The `<=` operator will select those artists born during or before 1400. Since there is an artist born in 1400 and an artist born before 1400, there are now two artists retrieved by the query.

## Checking for Nonmatches

In the previous examples, you have applied filters that select data that meet desired conditions. Sometimes it is easier to define the data you need by describing the values that should be excluded. For example, you may want to list all the artists who are not French. If you had to set up the filter only using matches, you would need to know all of the nationalities in the data and add conditions to include each nationality that isn't French. If there are French, English, and Canadian artists, the WHERE clause would need conditions to include the English and Canadian artists and not the French. Imagine how difficult this would be if there are artists from 100 countries in the list. The WHERE clause would also need to be modified when an artist with a new nationality is added to the data.

In this case, it is much easier to create a criterion that excludes the French artists. You can use a chat with an AI assistant to create the SELECT statement that will retrieve this data:

::: {.ai-conversation prompt="Write a SQL statement to display a list of artists, their nationality, and their birth. Show only those artists who are not French."}
> To display a list of artists, their nationality, and their birth, showing only those artists who are not French, you can use the following SQL statement:
>
> ```sql
> SELECT full_name, nationality, birth
> FROM artist
> WHERE nationality <> 'French';
> ```
>
> This query selects the full_name, nationality, and birth columns from the artist table. The WHERE clause filters the results to include only artists whose nationality is not 'French'. The comparison operator <> is used to check for inequality. The resulting rows will contain the artist's full name, nationality, and birth year, excluding those with French nationality.
:::

**Try the SQL statement.**

```sql {.websql}
SELECT   full_name, nationality, birth
FROM     artist
WHERE    nationality <> 'French';
```

The condition in the WHERE clause uses the `<>` operator. This means that when the value in the nationality column is not French, it will be retrieved by the query. There are 306 artists with 17 different nationalities who are not French. Notice the single quotes around the word French in the WHERE clause. Anytime the value you wish to compare is text, it must be enclosed within single quotes. Quotes are not used when the values are numbers.

::: {.note}
> **When to Use Single Quotes in a Condition.** When a value used in a condition in the WHERE clause is not a number, it must be enclosed within single quotes.
:::

## Checking for a Range of Values

There are times that you want to retrieve data within a range of values. To do this, you use the BETWEEN and AND keywords in place of operators in the WHERE clause. For this condition to work, you need beginning and ending values for the range. When you use the BETWEEN and AND keywords, the DBMS will include data that matches the beginning and ending values. In other words, the condition BETWEEN 10 AND 20 is logically the same as the combined conditions >= 10 *and* <= 20.

::: {.note}
> **BETWEEN and AND.** The logical keywords BETWEEN and AND include the beginning and ending values. The condition:
>
> `age BETWEEN 45 AND 50`
>
> is logically the same as the condition
>
> `age >= 45 AND age <= 50`
:::

Suppose that you want to list the artists, their nationality, and their birth who were born between 1400 and 1500. You can use a chat with an AI assistant to create the SELECT statement that will retrieve this data:

::: {.ai-conversation prompt="Write a SQL statement to display a list of artists, their nationality, and their birth. Show only those artists born between 1400 and 1500. Use the keywords BETWEEN and AND."}
> Certainly! Here's the SQL statement using the keywords BETWEEN and AND to display a list of artists, their nationality, and their birth, showing only those artists born between 1400 and 1500:
>
> ```sql
> SELECT full_name, nationality, birth
> FROM artist
> WHERE birth BETWEEN 1400 AND 1500;
> ```
>
> In this query, the BETWEEN keyword is used to specify the range of values, and the AND keyword is used to define the upper and lower bounds. The WHERE clause filters the results to include only artists whose birth year is between 1400 and 1500, inclusive. The resulting rows will contain the artist's full name, nationality, and birth year, limited to those born between 1400 and 1500.
:::

**Try the SQL statement.**

```sql {.websql}
SELECT   full_name, nationality, birth
FROM     artist
WHERE    birth BETWEEN 1400 AND 1500;
```

This example uses the keywords BETWEEN and AND to define a criterion that includes values for the birth column that fall in the range of 1400 to 1500. The query returns 17 artists whose birth is in years within this range. The query will include the beginning and ending values for the birth column. In other words, it will retrieve artists whose birth falls in 1400 or 1500, if there are any.

## Checking for No Value

There are times when some of the entries in a column contain no values. There is a special term for this situation: that entry is said to contain a NULL value. A NULL value is not 0, a space, or even a blank block of text. It is just the absence of data.

::: {.term}
> **NULL** — When an entry for a column of data is empty, it is called a NULL value. NULL values are not 0, spaces, or even a blank collection of text. It is the absence of data for that column.
:::

When creating a criterion to filter for NULL values, you need special syntax. The logical statement `column = NULL` will not work. To check if a value is NULL, use the keywords IS NULL.

Suppose that you want to list the artist's first and middle names for those entries on the artist table with a NULL value for the artist's middle names. You can use a chat with an AI assistant to create the SELECT statement that will retrieve this data:

::: {.ai-conversation prompt="Write a SQL statement to display a list of first and middle names for all artists with a NULL value for middle_names."}
> To display a list of first and middle names for all artists with a NULL value for middle_names, you can use the following SQL statement:
>
> ```sql
> SELECT full_name, middle_names
> FROM artist
> WHERE middle_names IS NULL;
> ```
>
> This query selects the first_name and middle_names columns from the artist table. The WHERE clause filters the results to include only artists whose middle_names column is NULL. The resulting rows will contain the first name and middle name (NULL) of artists with a NULL value for middle_names.
:::

**Try the SQL statement.**

```sql {.websql}
SELECT   full_name, middle_names
FROM     artist
WHERE    middle_names IS NULL;
```

This query lists all of the artists without middle names. Notice that 273 of the 421 artists on the artist table meet this criteria. NULL values do not always behave as you expect they might. For example, if you were to create a query to list all artists whose middle name is not "Van," you would expect to see all of the artists with a middle name other than "Van" — including those artists without a middle name. NULL values don't work that way, though. NULL values are not retrieved when you filter for non-matches. The syntax for this query is:

```sql {.websql}
SELECT   full_name, middle_names
FROM     artist
WHERE    middle_names <> 'Van';
```

Notice that all of the artists retrieved by the query have middle names. None of the artists with a NULL value for the middle_names column are included in the query result, even though those artists' middle names are also not "Van."

::: {.caution}
> **NULL Values and Non-Matches.** NULL values are not retrieved when you filter for non-matches using the <> or != operators.
:::
